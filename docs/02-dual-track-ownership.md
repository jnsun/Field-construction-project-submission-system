## 2. 文件所有权

| 区域 | 唯一所有者 | 可修改范围 | 其他泳道规则 |
| --- | --- | --- | --- |
| 数据库与 Supabase | Web/后端 | `sql/**`、`supabase/**`、数据库迁移、RLS、Storage 策略、RPC、服务端微信集成 | 小程序不得直接修改；接口缺口走 C01。 |
| 服务端规则与共享契约 | Web/后端 | 认证、状态机、资格/考试/复训规则、`docs/contracts/**`（C01 申请文件例外） | 小程序只消费已发布契约，不复制规则。 |
| Web/H5 与部署 | Web/后端 | `index.html`、`js/**`、`css/**`、`tools/**`、`.github/**` | 小程序不得修改。 |
| 微信小程序客户端 | 小程序 | `miniprogram/**`、页面、组件、客户端 SDK、缓存、微信客户端能力和客户端测试 | Web/后端不得修改。 |
| 集成与发布 | 集成线 | 仅合并已验收提交、联合测试记录、发布候选记录 | 不直接开发业务功能，不修改迁移、RLS、服务端规则或客户端页面。 |
| 跨线文档 | 发起泳道 | `docs/handoffs/<任务>-*.md`、C01 申请或响应文件 | 一次只由一个泳道创建一个新文件；已发布记录不可覆盖，后续结论另建文件。 |

除 C01 文档外，两个开发线程不得同时修改同一文件或同一所有权区域。发现冲突时停止编辑，记录当前 HEAD、文件路径和需求编号，再创建交接或 C01 文件；不得通过复制一套服务端逻辑、客户端规则或手工拼接迁移绕过。

## 3. 契约与 C01 规则

1. API 契约、原因码、权限范围、事件 schema、生成类型、Mock 和契约测试由 Web/后端发布。D04 尚未形成冻结契约，当前小程序只可使用匿名测试数据与 Mock。
2. 小程序发现接口不足时，在 `docs/contracts/change-requests/` 新建 `CR-<任务>-<序号>.md`，模板见 [C01 模板](changes/C01-template.md)。提交后不得改写原申请。
3. Web/后端接受或拒绝申请时，新建同编号的 `CR-<任务>-<序号>-response.md`。接受后才可修改服务端；实现必须同步契约、类型、Mock、测试和交接记录。
4. 任何破坏性变化必须发布新契约版本和兼容期。未冻结、未接受或未合并的接口不得被小程序作为真实业务依赖。

## 4. 交接机制

交接目录和文件命名规则见 [交接目录说明](handoffs/README.md)。每次已验收任务至少交付：任务与验收编号、泳道、工作树/分支/HEAD、实际修改文件、数据库与契约版本、测试结果、环境变量名称、回滚点、C01 状态和下一任务前置。

集成线只接收已提交且有上述交接记录的提交。合并顺序固定为：数据库/后端与契约、Web/H5、小程序、联合测试。集成线不替代任何一条开发线的代码审查或验收。

## 5. 环境、测试数据与恢复边界

| 环境 | 当前状态 | 数据规则 | 配置方式 |
| --- | --- | --- | --- |
| development | 已定义 | 本机开发；不得指向正式库 | `.env` 中仅设置变量值，参见 `.env.example`。 |
| test | 已配置 | 指定 Supabase 测试项目，仅匿名 `D02-TEST` 夹具 | `SAFETY_ENV=test`、测试项目 URL/anon key/数据库连接串。 |
| staging | 预留，未创建 | 发布前人工验收；禁止真实员工资料 | 创建独立项目和域名后才可配置。 |
| production | 预留，未创建 | 正式业务；禁止 D02 夹具、清理和测试密钥 | 仅在正式发布审批后单独配置。 |

测试环境包含 10 类匿名人员、普通/高风险/暂停/重开项目状态、私有测试桶和站内提醒替身。夹具、备份、恢复和清理流程见 [本地测试环境](02-local-test-environment.md)：备份默认忽略 Git，清理仅按 `safety_test_fixture_registry` 中的 `D02-TEST` UUID 执行，且必须带 `D02_TEST_ONLY` 确认值。文档和仓库只记录变量名，不记录密码、密钥或真实个人信息。
